# Phase 10C — Evidence-Backed Astralyn Character Taxonomy

## Scope and method

This audit covers the 83 characters that entered Phase 10C with `roles: ["unknown"]` and `mechanicTags: ["unknown"]`. The original nine curated characters are intentionally excluded from the enrichment overlay and remain byte-for-byte unchanged.

Each assignment was reviewed against the character's official HoYoWiki kit page as of HSR 4.5. HoYoWiki is Tier A under `docs/07-SOURCE_POLICY.md`. The `roles` and `mechanicTags` values are Astralyn-derived taxonomy: HoYoverse supplies the mechanics, while Astralyn maps those mechanics to the existing closed enums. Path alone, keyword scans, tier/meta strength, and preferred-team assumptions were not used.

`taxonomyEvidence.evidence` summarizes the verified source facts, while its `FactProvenance` records the source authority and review date. `roles` and `mechanicTags` are Astralyn's mapping from those facts. `tier_a_official` applies to the source facts only; it does not mean HoYoverse authored or endorsed either Astralyn label set. No separate taxonomy confidence score is published. If a future page no longer supports an assignment, that character must return to `unknown` until reviewed.

Mechanic tags describe observed behavior and need not duplicate the official ability-type label. For example, Astralyn maps a sequence of repeated random-target hits to `bounce` even when the containing official ability is labeled AoE. This mapping still requires the cited kit text to describe the random-target sequence.

## Maintenance boundary

`packages/shared/src/knowledge/fixtures/canonical-characters.ts` remains generated roster/kit data. Phase 10C taxonomy and evidence live in `character-taxonomy.ts`, so regenerating the canonical roster cannot silently erase or recreate taxonomy. New or changed taxonomy requires an official-kit review, a dated provenance record, and regression checks.
